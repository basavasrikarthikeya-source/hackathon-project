1. EXECUTIVE SUMMARY & SYSTEM ARCHITECTURE
================================================================================

SatQuery (Drishti) is a mission-critical satellite imagery query and change-
detection platform built for government officers ("Model Flags, Humans Decide").

The system architecture follows the LOCKED CONTRACT (v1.0):
- COMMAND CHANNEL (Doorbell): A Gradio public tunnel (share=True) running on 
  Kaggle. It carries ONLY tiny positional arrays: [job_id, prompt, image_paths].
  Never carries raw binary image data.
- DATA CHANNEL (Single Source of Truth): Supabase (Postgres + Storage + Realtime).
  Original satellite captures, AI-marked output images, job rows, status flips,
  and chat history live exclusively in Supabase.
- INVARIANT: Browser never talks directly to Kaggle, and Kaggle never talks 
  directly to the browser. Supabase is the shared memory between them.

3. HOW IT WAS DONE (TECHNICAL IMPLEMENTATION DETAILS)
================================================================================

1. Direct Cloud DDL via Supabase Management API:
   Instead of requiring manual browser interactions, a script 
   ('scripts/setup_supabase_remote.mjs') was written to communicate with 
   https://api.supabase.com/v1/projects/itpfveokpvzcbmoogcui/database/query.
   It executed 'supabase_setup.sql', creating tables, RLS policies, storage 
   buckets, and postgres publications in a single atomic transaction.

2. Automated Credential Provisioning:
   Queried https://api.supabase.com/v1/projects/itpfveokpvzcbmoogcui/api-keys to 
   retrieve the legacy and publishable keys. The 'service_role' key (which bypasses 
   RLS so the worker can update any job) was automatically written to the Kaggle 
   notebook and local config.

3. Python Synthetic Terrain Generator:
   Used Python PIL to generate synthetic satellite terrain featuring rivers, 
   forests, structures, and annotated bounding boxes (normalized 0-1000 converted 
   to pixel coordinates) matching the format expected by the Qwen2.5-VL system prompt.

4. Multi-Image Contract Enforcement:
   In 'backend/kaggle_worker.py', the worker checks the image count. When 2 images 
   are provided ([before, after]), the VLM describes changes and the drawing 
   engine strictly draws the bounding boxes onto imgs[-1] (the "After" image), 
   honoring Section 9 of ARCHITECTURE-LOCK.
